# HY2 服务端 UDP 乱序恢复（UDP Reorder）

[返回功能目录](../features.md)

HY2 服务端按客户端的包序号，恢复同一 UDP 会话内被网络调换的数据报，再交给出站。面向游戏等会把迟到的旧包计为丢包的 UDP 应用。

## 使用方式

没有配置开关。hysteria 入站为客户端打开的每个 UDP 会话自动启用；Xray 作为 HY2 客户端时不处理。

只对按会话连续编号的客户端生效。sing-quic 系客户端（如 mihomo）每条消息的包序号递增，同一消息的分片共用序号。会话要先连续出现递增序号才会暂存数据报；包序号恒为 0 或分片随机取值的客户端（Xray 客户端、官方客户端）照常直通。

## 状态与边界

- 按序到达的数据报立即交付，不增加延迟。
- 序号出现不超过 32 的缺口时，先到的数据报最多暂存 2 ms，缺口补上即按序交付；超时则放弃缺口按序放行，之后迟到的包直接交付。
- 缺口超过 32 视为丢包过多或计数重置，立即交付并重新确认连续性；单会话最多暂存 64 个数据报。
- sing-quic 以 65535 取模计数、不发送 0xFFFF，跨越回卷不算缺口。
- 只恢复服务端收到的上行顺序，不改变服务端发出的包序号，下行乱序仍需客户端处理。

2026-09-17 实测战争雷霆经 mihomo 连接：上行 8.4% 的数据报在国内至东京的线路上被调换，调换的相邻包到达服务器网卡时最多相差 0.11 ms，mihomo 与 Xray 自身未打乱顺序。
